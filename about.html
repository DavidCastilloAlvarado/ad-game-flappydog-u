about

the short version: free browser games, one developer, and a lot of local AI

What Is This Place?

This is an arcade — not the coin-operated, sticky-floor kind, but the browser kind. It is a small, growing collection of free games that run entirely inside your browser. No downloads, no installs, no accounts, no build steps. You open a page, you hit play, and the game is running.

The current lineup: Flappy Dog, Star Striker, Solar System Simulator and Bean Dash. The shelf is not finished — when a new game makes it through testing, it gets its own page and a card on the home screen. The whole collection lives in a single games/ folder, one subdirectory per game.

Who Is Behind It?

The games are built by David, a developer who favors small, fast, single-purpose projects over sprawling ones. The common thread across the arcade is the stack: plain HTML, CSS and JavaScript. No frameworks, no build tools, no game engines — with one admitted exception, since Bean Dash leans on Three.js to render its 3D chaos. Each game is a handful of files in a folder, served statically. That constraint is not an accident; it is the point. Small projects stay fast to ship, fast to host, and fast to understand when something breaks.

What makes these projects a little unusual is the process. Most of the code — the games themselves, and most of the text on this site — is generated by a local AI model running on consumer hardware, not by a cloud API. The workflow is a conversation: describe what should happen, let the model draft it, read the output with a critical eye, ask for changes, and repeat until the result is worth keeping. The human part is deciding what to build, reviewing every line, and knowing when "good enough" has actually been reached.

Flappy Dog was the first project to go the full distance, from an empty folder to a deployed, monetized product in about five prompts. If you want the complete story — including the failures along the way — the development blog has it.

How It Is Built and Deployed

Everything here is static: HTML, CSS and JavaScript served by nginx from a Docker image. The pipeline is fully automated — a GitHub Actions workflow builds and pushes the container image on every commit to main, then deploys it to Google Cloud Run using Workload Identity Federation, so no long-lived credentials ever sit in the repository or the pipeline. The whole site, every game included, ships as one image and is served at flappydog.peruf.me.

Runtime state stays on your machine. High scores live in your browser's localStorage, your settings live on your device, and nothing about how you play is sent anywhere. When a page shows ads through Google AdSense, that is the only thing that leaves your browser.

Why Is There This Much Text?

A practical one: Google AdSense wants a site to carry a meaningful amount of original content before it approves it for ads. The games are the real product; the words exist to keep the site monetized so it can stay online for free. If you came here to play, you are allowed to skip the reading and hit the play button — the text will still be here when you get back.
